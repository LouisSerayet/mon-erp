# Scripts SQL — mon-erp

Scripts à exécuter manuellement dans Supabase → SQL Editor. Aucun n'est exécuté automatiquement par l'app.

| Fichier | Statut | Description |
|---|---|---|
| `01_backfill_prevu_lignes.sql` | ✅ Déjà exécuté | Recopie les lignes de devis vers les projets créés depuis un devis accepté (bug corrigé depuis dans le code). |
| `02_sync_montant_ht_global.sql` | ✅ Déjà exécuté | Resynchronise le CA (`montant_ht`) des projets à partir de leurs lignes (lots + lignes sans lot). |
| `03_rls_activation.sql` | ✅ Déjà exécuté | Active la sécurité (RLS) sur toutes les tables — accès réservé aux utilisateurs connectés. Vérifié : connexion + accès aux données OK après activation. |
| `pennylane_migration.sql` | ✅ Déjà exécuté | Colonnes pour l'intégration Pennylane (adresses structurées, identifiants Pennylane, suivi de synchro). L'intégration code est en place mais le jeton API Pennylane n'est pas encore configuré sur Vercel — à faire plus tard avec l'expert-comptable. |
| `qonto_migration.sql` | ⏳ À exécuter | Colonnes pour le rapprochement Qonto <-> factures clients/fournisseurs (`qonto_transaction_id`, `qonto_matched_at`, `qonto_match_confiance`) — nécessaire avant d'utiliser la page "Rapprochement" ou les boutons "Vérifier sur Qonto" d'un projet. |
| `depenses_generales_migration.sql` | ⏳ À exécuter | Crée la table `depenses_generales` (loyer, comptabilité, assurance, abonnements...) utilisée par la nouvelle page "Dépenses" — dépenses de la société non liées à un projet client. Inclut RLS, suppression douce (Corbeille) et rapprochement Qonto. Nécessite que `06_corbeille_soft_delete.sql` et `07_historique_modifications.sql` aient déjà été exécutés. |
| `commandes_statuts_migration.sql` | ⏳ À exécuter | Remappe les commandes fournisseurs existantes vers le nouveau schéma à 3 statuts (Brouillon / Validée / Annulée) — à exécuter après le déploiement du nouveau code de "Commandes frs" dans un projet. |
| `tva_taux_migration.sql` | ⏳ À exécuter | Ajoute une colonne `taux_tva` (20 / 10 / 5,5 / 0, défaut 20) sur `devis` et `projets`, pour choisir si/comment la TVA s'applique à un devis + sa facture client (les commandes fournisseurs restent à 20 %). Le code retombe sur 20 % tant que la colonne n'existe pas, donc pas d'urgence particulière à l'ordre déploiement/migration. |
| `regime_tva_commandes_migration.sql` | ⏳ À exécuter | Ajoute une colonne `regime_tva` ("normale" / "autoliquidation", défaut "normale") sur `commandes` — pour les achats en autoliquidation TVA (sous-traitance BTP, article 283 du CGI), au niveau de chaque commande individuelle. Le code retombe sur "normale" (20 %) tant que la colonne n'existe pas. |
| `fusion_devis_projets_migration.sql` | ⏳ À exécuter | Fusionne l'ancien onglet "Devis" (tables `devis`/`devis_lignes`) dans "Projets" : un projet démarre désormais directement en devis (statut "Brouillon"). Migre chaque devis pas encore transformé en projet vers une nouvelle fiche projet (statut mappé, lignes copiées) ; les devis déjà convertis via l'ancien bouton ne sont pas re-migrés. **À exécuter après `tva_taux_migration.sql` et après le déploiement du nouveau code (onglet "Devis" supprimé).** Contient une section de nettoyage (suppression de `devis`/`devis_lignes`) volontairement commentée, à activer seulement après vérification manuelle. |
| `categorie_ligne_migration.sql` | ⏳ À exécuter | Ajoute la "nature" d'une ligne (`categorie_ligne` : negoce / option / variante / texte, + `variante_active`) sur `projet_lignes` — pour proposer des Options hors total principal et des Variantes alternatives dans l'onglet Lignes. Le code retombe sur "négoce" (ligne classique) tant que les colonnes n'existent pas, donc pas d'urgence particulière à l'ordre déploiement/migration. |
